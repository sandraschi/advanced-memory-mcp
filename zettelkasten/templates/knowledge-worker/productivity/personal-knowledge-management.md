# Personal Knowledge Management

Building a system to capture, organize, and retrieve knowledge effectively.

## Why PKM Matters

### Information Overload
We consume but don't retain. PKM creates lasting value from learning.

### Connect Ideas
Best insights come from connecting disparate concepts.

### Build on Past Learning
Avoid re-learning. Build cumulative knowledge.

### Creative Output
Well-organized knowledge base fuels creation.

## Core Principles

### 1. Capture Everything
Your brain is for having ideas, not storing them.

**Tools**:
- Quick capture app (phone)
- Inbox folder (computer)
- Physical notebook (always accessible)

**Process Later**: Capture now, organize later.

### 2. Progressive Summarization
Tiago Forte's method: Layer highlighting.

**Levels**:
1. **Original text**: Full capture
2. **Bold**: Most interesting passages
3. **Highlight**: Best of bold
4. **Executive summary**: Synthesis in your words
5. **Remix**: Use in new creation

### 3. Link Thinking
Connect related notes. Value emerges from connections.

```
# Note on Habit Formation
Links to:
- [[Willpower]]
- [[Behavior Design]]
- [[Identity]]
- [[Environment Design]]
```

### 4. Atomic Notes
One idea per note. Small, reusable, combinable.

```
❌ Big note: "Everything about productivity"
✅ Atomic: Separate notes for:
- [[Pomodoro Technique]]
- [[Deep Work]]
- [[Time Blocking]]
```

## The Zettelkasten Method

### Principles
**Atomic**: One idea per note
**Autonomous**: Understandable alone
**Connected**: Links to related notes

### Note Types

**Literature Notes**: From external sources
```
# Atomic Habits - James Clear

Key insight: Focus on systems, not goals.

Small habits compound over time. 1% better daily =
37x better in one year.

Links: [[Compound Effects]], [[System Design]]
```

**Permanent Notes**: Your insights
```
# Systems Beat Goals

Goals are outcome-focused. Systems are process-focused.

Better: Instead of "lose 20 pounds" (goal), adopt
"exercise 30 min daily" (system).

Why: Goals are temporary. Systems create lasting change.
```

**Index Notes**: Structure and find
```
# Productivity MOC

## Time Management
- [[Pomodoro Technique]]
- [[Time Blocking]]
- [[Energy Management]]

## Focus
- [[Deep Work]]
- [[Attention Management]]
- [[Digital Minimalism]]
```

### Workflow
1. Read/Learn something
2. Take literature notes
3. Write permanent notes (your insight)
4. Link to related notes
5. Update index notes

## PARA Method

Tiago Forte's organizational system.

### Structure
```
Projects/     # Active work (finish line)
Areas/        # Ongoing responsibilities
Resources/    # Topics of interest
Archive/      # Inactive items
```

### Projects
Active work with deadline and deliverable.

**Examples**:
- "Q1 Marketing Campaign"
- "New Website Launch"
- "Learn Python for Data Analysis"

**Action-Oriented**: Clear next steps.

### Areas
Ongoing responsibilities without end date.

**Examples**:
- "Health & Fitness"
- "Finance"
- "Professional Development"
- "Home Management"

**Standard to Maintain**: Track over time.

### Resources
Reference material for interests.

**Examples**:
- "Writing Techniques"
- "Recipes"
- "Travel Ideas"
- "UX Design Patterns"

**Just in Case**: No active work.

### Archive
Inactive projects and areas.

**Review**: Annually, move inactive items.

## CODE Method

Also by Tiago Forte: Capture, Organize, Distill, Express.

### Capture
Save valuable information.

**What to Capture**:
- Highlights from reading
- Insights from conversations
- Ideas that emerge
- Useful examples

**Where**: Quick capture tool → inbox.

### Organize
Sort by actionability (PARA).

**Ask**: "Where will this be useful?"

### Distill
Progressive summarization: Make scannable.

### Express
Create something: Writing, presentation, project.

**Goal**: Make captured knowledge actionable.

## Tools

### Note-Taking Apps

**Roam Research / Logseq**:
- Outliner-based
- Automatic bidirectional links
- Daily notes
- Graph view

**Obsidian**:
- Markdown files (future-proof)
- Local-first (you own data)
- Graph view
- Extensive plugins
- Advanced Memory (MCP integration!)

**Notion**:
- All-in-one workspace
- Databases
- Collaboration
- Templates

**Bear / Apple Notes**:
- Simple, clean
- Apple ecosystem integration

### Choosing Tools

**Questions**:
- Markdown or proprietary format?
- Local or cloud?
- Plain text or rich formatting?
- Mobile support needed?
- Link features?

**Philosophy**: Simple system used > complex system abandoned.

## Retrieval

### Search
Full-text search across all notes.

**Naming**: Clear, descriptive titles.

### Links
Follow connections between ideas.

### Tags
Categorize by theme, project, or type.

```
#productivity
#research
#project/website-redesign
```

### MOCs (Maps of Content)
Index notes that organize topics.

```
# Writing MOC

## Craft
- [[Show Don't Tell]]
- [[Character Development]]
- [[Plot Structure]]

## Process
- [[Writing Habits]]
- [[Editing Checklist]]
- [[Publishing Guide]]
```

## Best Practices

### Review Regularly
- **Daily**: Process inbox
- **Weekly**: Review active projects
- **Monthly**: Update areas and resources
- **Yearly**: Archive and reflect

### Write for Future Self
Assume you'll forget context. Make notes self-explanatory.

### Link Generously
When you see connection, create link. Network effects compound.

### Don't Over-Organize
Perfect organization isn't the goal. Usefulness is.

### Start Small
Simple system you actually use > complex system you abandon.

## Common Pitfalls

### Collector's Fallacy
Saving ≠ Learning. Must engage with material.

**Fix**: Always add your own thoughts, links, or summary.

### Over-Organizing
Spending more time organizing than creating.

**Fix**: Organize just enough. Use when needed.

### No Review Process
Capturing without revisiting = digital hoarding.

**Fix**: Weekly review cadence.

### Perfectionism
Waiting for perfect system prevents starting.

**Fix**: Start simple, evolve over time.

## Advanced Techniques

### Spaced Repetition
Review notes at increasing intervals.

**Tools**: Anki, RemNote

**For**: Facts, languages, concepts to memorize.

### Evergreen Notes
Andy Matuschak's concept: Notes that grow and improve over time.

**Characteristics**:
- Concept-oriented (not book-oriented)
- Densely linked
- Regularly updated
- Atomic

### Digital Gardens
Public notes that grow and evolve.

**Benefits**:
- Learning in public
- Feedback from others
- Forces clarity
- Helps others

## Workflow Example

```
1. Read article on productivity
2. Highlight key points while reading
3. After reading, create literature note
4. Extract 2-3 permanent notes (your insights)
5. Link to existing related notes
6. Update relevant index note
7. File in appropriate PARA folder
```
